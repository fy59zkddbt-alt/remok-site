# Интеграция публикационной V4 с Tilda

Структура этой версии отличается от исходной локальной папки: index.html, styles.css и script.js находятся в корне; cases/ содержит четыре HTML-страницы; assets/images/ и assets/cases/ — только используемые медиа. Папки v4/ в репозитории нет.

## GitHub Pages

В настройках репозитория Pages выберите ветку main и / (root). Сборка не нужна. Не переносите файлы из assets/ и не меняйте регистр имён. Фактический HTTPS-адрес страницы возьмите из настроек после успешного развёртывания. Ниже PAGES_BASE — этот адрес с завершающим /, а не строка для буквальной вставки.

## Tilda

Создайте отдельную страницу с блоком T123 «HTML-код». Вставьте содержимое body из корневого index.html без doctype/html/head/body. Header, footer и мобильная панель уже входят в HTML; не дублируйте их стандартными блоками Tilda. Iframe не нужен, Zero Block не требуется.

В head подключите CSS по PAGES_BASE + styles.css и JS один раз с defer по PAGES_BASE + script.js. Не используйте async. Перенесите title, description и язык в настройки Tilda. Единственный H1 уже в разметке. Проверяйте опубликованную страницу: [официальная инструкция T123](https://help.tilda.cc/html).

## URL в копии HTML для Tilda

- assets/images/… → PAGES_BASE + assets/images/…
- assets/cases/… → PAGES_BASE + assets/cases/…
- cases/*.html → PAGES_BASE + cases/*.html, если кейсы остаются на Pages.
- При встраивании кейсов в Tilda ../assets/… → PAGES_BASE + assets/…
- Возвраты из кейсов ../index.html#… → фактический URL главной Tilda с сохранением якоря, когда он будет известен.

Проверьте src, poster, source и ссылки на видео. Локальные якоря главной, tel, mailto, WhatsApp, Telegram и ссылки отзывов оставьте без изменений. Не добавляйте общий base. Основной сайт в репозитории продолжает использовать относительные пути.

Если кейсы остаются на Pages, их возвраты пока ведут на главную Pages. Для единой навигации потребуется согласовать URL Tilda и обновить возвраты в публикационной копии. Для встраивания всех кейсов создайте ещё четыре страницы Tilda с соответствующим HTML.

## Проверка и ограничения

CSS содержит общие правила для body/header/nav/a/img и полей. Проверьте совместимость со стилями и обёртками Tilda, отступы T123, sticky header и fixed mobile contacts. При конфликте подготовьте отдельный адаптер, не меняя рабочий дизайн основной версии.

Формы не отправляют данные: стандартные HTML-формы не подключаются к Tilda автоматически. Согласуйте получателя, интеграцию и юридические документы, затем подтвердите реальную доставку тестовой заявки. Не подключайте два обработчика отправки.

Проверьте главную и четыре кейса, Network без 404, Console без ошибок, все фото и видео без autoplay, внешние контакты и якоря. Проверьте три профиля, семь вариантов отделки и пороги условий 5/8/9/11 м²; скидка не вычитается автоматически.

Проверьте ширины 1920/1440/1280/1024/768/480/390/360, фокус и клавиатуру, мобильную панель с safe-area, отсутствие horizontal overflow. После выбора домена согласуйте основную индексируемую версию и canonical. Фотография директора и юридические документы пока остаются незавершённым контентом.
